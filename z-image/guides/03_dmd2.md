# 实验 3：正式训练 DMD2 基线

**目的**：对照基线。DMD2（官方 SDXL 配置：batch 128，TTUR 5，lr 5e-7，GAN 5e-3/1e-2）蒸馏同一个 2 步 student。real score 是未蒸馏的 `Tongyi-MAI/Z-Image`（CFG 4），fake score 是它的可训练副本加 GAN head；真实数据是 Turbo 的 reference 图，已编码好放在 HF（`jiachengcui888/zimage-dmd2-latents`，~18 GB）。**花的 GPU 时间和 ours 一样**（读 ours 的日志）。

**前提**：实验 1（ours，`01_ours.md`）已经在**同一个 `--root`** 上跑完（或者用户给 ours 的 GPU 小时数）。

**机器**：8×A100/H100 80GB（最少 4 卡：要同时放三个 6B 模型）。**时间**：≈ ours 的训练时间 + 下载 Z-Image（~25 GB）+ latents（~18 GB）+ 评测 ~1 h。

> 给 coding agent（Codex / Claude Code）：这份文件是自包含的，按顺序做即可。

## 给 agent 的规则（必读）

1. **只做本文件这一个实验。** 不要顺手跑别的脚本。
2. **不要改代码。** 只运行本文件里的命令。脚本报错时，把命令、报错和日志最后 30 行交给用户，不要自己改 `.py` / `.sh`。
3. **长任务放进 tmux 后台**（会跑几小时，超过 agent 单条命令的超时），然后定期看日志：
   ```bash
   tmux new -d -s <名字> "<命令> 2>&1 | tee /root/<名字>.out"
   tail -n 30 /root/<名字>.out     # 进度
   tmux ls                         # 还在不在跑
   ```
   不要因为“好像没动”就杀进程：先 `nvidia-smi`，GPU-Util 接近 100% 就是在算。
4. **用 prompt 给的设置**：用户的 prompt 里给了仓库目录、大数据目录（`--root`）和 GPU 数。下文命令里的 `/root/RDM`、`/root/rdm-sets` 一律换成 prompt 里的值，脚本按 GPU 数选；prompt 没给的才问用户。wandb 不用你管：用户已经登录过，**不要向用户要 key，也不要处理 key**。
5. **不要删除** `--root` 下的任何东西，除非用户明确同意。
6. **失败了先重跑同一条命令**：已完成的阶段会自动跳过；训练中断加 `--resume`。
7. **结束时**把脚本最后打印的结果表原样交给用户。

## 运行（以 8 卡为例）

```bash
cd /root/RDM
bash z-image/scripts/dmd2_eight-cards.sh --root /root/rdm-sets --latents-hf jiachengcui888/zimage-dmd2-latents --dry-run
tmux new -d -s dmd2 "bash z-image/scripts/dmd2_eight-cards.sh --root /root/rdm-sets --latents-hf jiachengcui888/zimage-dmd2-latents 2>&1 | tee /root/dmd2.out"
```
- 每 5 个 iteration 有 1 个更新 student（`[student]`），其余只更新 fake score。看 `dmd`、`gan_g`（student）和 `fake`、`gan_d`、`d_real`/`d_fake`（fake score / 判别器）。
- 中断后加 `--resume`；只差评测加 `--eval-only`。
- wandb：group `dmd2`。

## 出问题时

| 现象 | 怎么办 |
|---|---|
| 网络断了 / 进程被杀 | 重跑同一条命令（训练加 `--resume`，只差评测加 `--eval-only`） |
| `already holds a run` | 已有同名 run。续跑加 `--resume`；要重来先问用户，再 `mv <run 目录>{,_old}` |
| `CUDA out of memory` | 不要改参数；把出错阶段和日志最后 30 行交给用户 |
| 磁盘满 | `df -h` 报告用户；只有**已评测过**的 `step_*.pth` 可以删，且要先问 |
| 很久没新输出 | 准备阶段（下载、重建 contexts）和 RDM 的单步本来就要很久；看 `nvidia-smi` |
| wandb 没数据 | `cat <run 目录>/logs/wandb_watch.log` 看原因 |

报告问题时附上：命令、`git log --oneline -1`、日志最后 30 行、`nvidia-smi`、`df -h`。
